战斗数据设计

本章节汇总战场系统的数据设计，包含敌人模板、敌人阵容、战场模板和副本配置四类数据。

快速查询：使用 战斗数据查询器 在线浏览所有战斗数据。

数据关系总览

战斗数据的设计遵循以下依赖关系：

敌人模板 (enemies.json)          ← 八维属性 + 技能 + AI + 奖励配置
     ↓ 引用 enemyId
敌人阵容 (enemy-groups.json)     ← 敌人 + 阵型位置 + 可选覆盖
     ↓ 引用 groupId
战场模板 (battle-templates.json) ← 布局规模 + 可选驻守敌人
副本配置 (dungeon-templates.json)← 关联地图/敌人组/队列时长/奖励包
     ↓ deployBattle
战斗引擎                         ← 生成 BattleUnit 执行战斗

数据文件索引

文件 内容 设计文档

enemy-groups.json 敌人阵容配置：引用敌人模板 + 阵型位置 + 可选 overrides 战场系统设计 §7.9

敌人模板（Enemy）

敌人模板定义了一个战斗单位的完整属性。核心设计原则：

  • 敌我同源：敌人与玩家的底层数据结构一致，阵营只是标签
  • 八维驱动：attributes（八维）是唯一属性来源，combatStats 由 character-templates.json 模板公式派生
  • 总等级 = 八维属性等级之和（如全5 = 40级）
  • 奖励分离：expReward 为经验池总额，rewardTableId 引用 rewardTables.json 中 trigger_type:5 的奖励表
  • 起始体重内部分组单位 0.01kg=1，小猪默认 800=8kg
  • 属性补正：modifiers 提供外部属性补正（abilityBonus/combatBonus），弥补敌人无装备系统的缺失

敌人属性表

字段 类型 说明
enemyId string 敌人模板ID（e_开头）
name string 敌人名称
description string 敌人描述
attributes object 八维属性（力量/体质/敏捷/灵巧/智力/感知/意志/魅力）
startingWeight number 起始体重（0.01kg=1）
skills array 技能列表 [{skillId, level}]
ai object AI 行为配置（targetRule/skillPriority/aoeTargetRule）
expReward number 经验池总额
rewardTableId number 掉落表ID（引用 trigger_type:5）
modifiers object 外部属性补正：abilityBonus（八维加成，模板公式前）+ combatBonus（派生属性 flat 加成，模板公式后）+ startingWeight 补正

敌人阵容（EnemyGroup）

敌人阵容定义一场战斗中敌方单位的布局。核心概念：

  • 阵型位置：每个敌人指定 lane（路，从1开始）和 rank（排：front/mid/rear）
  • 战场布局：2×3 表示 2 路 × 3 排，最多容纳 6 个敌人
  • Overrides：可选字段，可覆盖敌人模板的 attributes/startingWeight/skills/modifiers 等，用于 boss/精英
  • groupId：被 battle-templates.json 和 dungeon-templates.json 引用

战场模板（BattleTemplate）

战场模板定义了战斗的规则空间：

  • 布局：lanes(1/2/3) × ranks(固定3)，决定战场网格
  • enemyGroupId：可选，无驻守时为 null（副本模式在创建时指定）
  • marchThreshold：行军阈值，行军进度达到此值后进入待战区
  • 战场独立于地图数据，通过引用关系关联

副本配置（DungeonTemplate）

副本入口配置，将地图/敌人/奖励串联为一个可挑战的关卡：

  • dungeonType：normal（普通）/ rare（稀有），决定消耗次数类型
  • dailyAttempts：每日重置次数限制
  • queueDuration：战斗队列倒计时（秒）
  • rewardPackId：通关奖励包，引用 rewardTables.json
  • 副本创建时通过 enemyGroupId 引用对应敌人阵容
